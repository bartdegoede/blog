Seven years ago I [gave this blog audio versions of its posts](/use-google-cloud-text-to-speech-to-create-an-audio-version-of-your-blog-posts/) with Google Cloud Text-to-Speech. Point a Python script at a Markdown file, get an MP3, embed it with a Hugo shortcode. It worked, it was mostly free, and I was pretty pleased with it. The little audio player has been sitting at the top of my posts ever since.

The problem is that it sounds like 2010. Every time I hit play I hear the flat, slightly seasick cadence of a Wavenet voice from the last decade, and it needs a Google Cloud project, an API key, and a billing account to regenerate. This is a blog that now does [semantic search in the browser from a 4 MB lookup table](/semantic-search-in-your-browser/); the narration should not be the most dated thing on the page.

So I replaced it. The new audio is generated by [Kokoro](https://huggingface.co/hexgrad/Kokoro-82M), an 82-million-parameter model that runs entirely on my M1 MacBook Air. No cloud, no key, no per-character bill. It is dramatically better, and I re-narrated all seven years of back catalogue in about fifteen minutes.<!-- more -->

## What changed: Kokoro and MLX

[Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M) is a small, Apache-2.0-licensed text-to-speech model that punches absurdly above its weight — it spent a good while at the top of the TTS Arena leaderboard for open models, beating things many times its size. The 82 million parameters matter: the weights are a few hundred megabytes, not the tens of gigabytes a large speech model wants. And it was trained mostly on long-form reading, which is exactly the job here. It is a narrator, not a chatbot voice, and it shows.

The thing that makes it practical on a laptop is [MLX-Audio](https://github.com/Blaizzy/mlx-audio), which runs Kokoro on Apple's [MLX](https://github.com/ml-explore/mlx) framework — natively on the Apple Silicon GPU, no PyTorch, no CUDA, no ONNX runtime. The whole "install" is:

```bash
pip install mlx-audio
```

and then, in Python, the entire synthesis step is:

```python
from mlx_audio.tts.utils import load_model

model = load_model("mlx-community/Kokoro-82M-bf16")
for result in model.generate(text="Hello there.", voice="af_heart", speed=1.0, lang_code="a"):
    audio = result.audio  # 24 kHz float32 samples
```

Kokoro ships 54 voices; I settled on `af_heart` for narration.

## Faster than real time (but be honest about the number)

The internet will tell you Kokoro runs at "15× real time and up" on Apple Silicon. When I re-narrated the whole blog — 14 posts, **two full hours of audio** — it took **922 seconds**, or a little over fifteen minutes. That is **7.8× real time** on my M1, measured end to end including all the Markdown parsing and MP3 encoding.

7.8× is not 15×, and I think it is worth saying so. The headline numbers you see quoted are usually the raw model on a warm cache doing nothing else; a real pipeline has overhead. But 7.8× is still the important kind of number: it means the model synthesizes speech far faster than you could ever speak it, on a fanless laptop, for the cost of some electricity. A curious side effect of MLX running on the GPU is that the process barely registers on the CPU — the `time` command reported about six minutes of CPU against fifteen minutes of wall clock, because the Metal GPU was doing the actual work and doesn't show up in CPU accounting.

## The jargon problem

There is one place Kokoro reliably falls on its face, and it is a place a blog like mine steps on constantly. Kokoro converts text to phonemes with [espeak-ng](https://github.com/espeak-ng/espeak-ng), and espeak-ng has never heard of my vocabulary. `int8` comes out as "int eight" if you are lucky and something worse if you are not. `RRF` gets read as a word. `Goldmark`, the Markdown renderer Hugo uses, becomes something with a hard *g* that isn't a name anyone would recognize.

The fix is boring and effective: a shared pronunciation lexicon, applied to the text before it ever reaches the model.

```yaml
# scripts/tts_lexicon.yaml — surface form -> spoken form
int8: "int eight"
RRF: "R R F"
Goldmark: "Gold mark"
espeak-ng: "e speak N G"
WordPiece: "word piece"
```

Matching is case-sensitive, whole-token, and longest-match-first, so `int8` wins over `int` and `int` never fires inside `printf`. When a new post mispronounces a term, I add a line. It is a spelling list for a machine that reads out loud.

## The pipeline

The rest is unglamorous plumbing, which is the point — the interesting part is a single `pip install`. A small Python package turns a post into an MP3 in five stages:

1. **Extract** the narratable prose from Markdown. I reused the exact `to_prose` function from [the semantic-search build](/semantic-search-in-your-browser/) — it already strips front matter, code blocks, and shortcodes — and added a pass to drop footnote markers and table pipes, which a narrator would otherwise read aloud as noise.
2. **Apply the lexicon** so the jargon is spelled the way it should sound.
3. **Chunk** the prose on sentence boundaries into bite-sized pieces.
4. **Synthesize** each chunk with Kokoro.
5. **Stitch** the pieces into one MP3.

A `click` CLI wraps it, with an `--all` flag that backs up the existing audio and re-renders every post behind a progress bar:

```bash
uv run python scripts/text_to_speech.py content/post/some-post.md   # one post
uv run python scripts/text_to_speech.py --all                        # the whole blog
```

I'll be honest that "runs on your laptop" always has an asterisk or two. Python 3.13 [removed the `audioop` module](https://peps.python.org/pep-0594/) that `pydub` needs, so there is a backport pinned in. Kokoro's English G2P needs a couple of extra packages that aren't installed by default. Getting from `pip install` to first sound took longer than the marketing implies. But once it runs, it runs offline, forever, for free.

## Free, local, and yours

In 2019 I needed a cloud API, a billing account, and a per-character price list to make my blog talk. In 2026 an 82-million-parameter model does it better, on a laptop with no fan, faster than the audio plays, and the only account involved is the one I use to `git push`. That is the same story as [the search box on the front page](/semantic-search-in-your-browser/): a capability that used to mean a datacenter now fits on the machine already on your desk.

The old robotic clips are safe in a backup folder. Everything you hear on the blog now came off my laptop.
